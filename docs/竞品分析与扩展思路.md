# 蛋白钱包 · 竞品分析与扩展思路(国内版)

2026-11-04 重写。上一版(2026-11-03)写于定位切到国内之前,竞品全是美国产品,见 git 历史。框架仍是「产品面试向 Vibe Coding 选题思路」那篇帖子:真实痛点 → 足够小的用户标签 → 验证 → 生态位(蓝海证需求、红海证细分更专业)→ 加法或减法。

## 1. 蛋白钱包在帖子框架里的位置

| 帖子的要求 | 现状 | 缺口 |
| --- | --- | --- |
| 从生活里真实的问题出发 | 自己健身、生活费有限,是核心用户 | 无 |
| 足够小的用户标签 | 在健身房练、想增肌、月生活费约 2000 元的国内大学生 | 无 |
| 社交平台搜关键词看真实抱怨 | 已做(2026-11-04,小红书手搜"穷鬼增肌"):饮食指南帖赞 5382 / 藏 4892;"两年花了 1.7w"赞 2846,蛋白粉折合每月 250 元;住校增肌饮食分享赞 1377,作者手工给每顿标蛋白克数;提问帖"穷鬼增肌吃什么呀"评论 82 | B 站和其他关键词还没搜;点赞不等于愿意用工具 |
| 应用商店低分评价 | 没做 | 看薄荷健康、Keep 的低分评价里有没有"食堂 / 外卖记不了""不管钱" |
| 找身边潜在用户聊 | 8 名健身房用户 + 国内同学 | 国内人数没记;三个关键问题没问(钱是不是第一障碍、怎么选吃饭地点、会不会换) |
| 生态位 | 红海(饮食记录),减法 + 加法 | 见下 |
| 新增价值要覆盖切换成本 | 记了几天才有回报 | 这是最大的缺口,第 4 节的方向 1、3 针对它 |

生态位是红海:饮食记录的需求已被市场验证。减法是只服务增肌大学生、只追蛋白和钱两个数。加法是补上"钱"这条线,产出 分/g。

## 2. 竞品分四类

| 类别 | 代表 | 它们做什么 | 做不到或不做的 |
| --- | --- | --- | --- |
| 通用 AI | 豆包、DeepSeek、通义、元宝 | 拍照或一句话,单次估算热量和营养;豆包和通义会按烹饪方式调整 | 不记账、不累计、不知道价格;给单点数字;每次都要重新问 |
| 垂类饮食记录 | 薄荷健康(160 万条食物库、AI 拍照、2026-07 获蚂蚁集团战略投资并接入蚂蚁阿福)、Keep,以及一批套了豆包 / DeepSeek 的"拍照识热量"小程序和 App | 为减脂和控热量设计,搜索条目 + 克数或拍照,会员订阅 | 单位是千卡不是钱;人群是减脂不是增肌;精确到个位的单点数字 |
| 记账 | 鲨鱼记账、钱迹、微信和支付宝账单 | 餐饮只是一个分类总额 | 不知道这笔钱买到了什么营养 |
| 校园食堂侧 | 高校智慧食堂系统和小程序(哈尔滨理工的智能称重台按菜显示营养;有中学小程序做营养展示和默认推荐) | 订餐、结算、按菜显示营养 | 属于学校采购的系统,绑硬件和单个食堂;管不到外卖、路边摊、宿舍自炊 |

## 3. 和通用 AI、垂类饮食记录的区别(面试要讲清的)

**和通用 AI(豆包 / DeepSeek)**:单次估算它们和我们一样准,甚至更准,因为底层是同一类模型。区别不在模型:

1. 它是一次问答,我们是一本账。今天还差多少、这周哪顿最划算、这个月蛋白花了多少,聊天窗口里的数字过了就没了。
2. 它不知道价格。分/g 需要钱和蛋白出现在同一条记录里。
3. 它让模型算数,我们让代码算数。能用官方表、标签、成分表的地方不让模型猜。
4. 它给单点数字,我们给区间、置信度和依据。
5. 我们有评测集,估得准不准是可测的。

坦白的风险:薄荷已经接进蚂蚁阿福,大厂把"拍照 + 记录"做成内置功能是时间问题。留得住的是"增肌 × 预算"这个它们不会专门服务的小人群,以及决策层(下一顿去哪吃)。

**和垂类饮食记录(薄荷 / Keep / 小程序)**:

1. 人群相反:它们服务减脂,看的是别超;我们服务增肌,看的是够不够、贵不贵。
2. 单位不同:它们的单位是千卡,我们的单位是每一块钱换多少克蛋白。
3. 交互不同:它们靠庞大的食物库加搜索和克数,我们只记两个数,常吃的一次点击。
4. 表达不同:它们精确到个位,我们给区间。

别把"拍照识别"说成差异点:薄荷也能拍。差异是钱和决策。

## 4. 食堂菜谱 feed 值不值得做

方向对,形态要换。

**对的部分**:帖子说新增价值要覆盖切换成本。现在的产品是"先记几天,才有回报";"吃之前帮你选"能在第一次使用就给出价值,而且选中即记录,手动录入变成副产品。

**每日菜谱 feed 这个形态的三个问题**:

1. 数据拿不到。国内食堂不公开每日菜单和营养数据,有数据的智慧食堂系统属于学校采购、绑硬件。一个人要给每所学校每天维护菜单,做不动。
2. "推荐"是指导行为,碰 Non-goal;生成建议也正是豆包、阿福最擅长的事,等于去别人的主场比。
3. feed 要每天更新才值得打开,一旦断更就没人看。

所以:要的是 feed 解决的那件事(差额之后去哪补),不要 feed 这个形态。

## 5. 六个方向

| # | 方向 | 做什么 | 数据从哪来 | 对应帖子 | 成本 |
| --- | --- | --- | --- | --- | --- |
| 1 | **拍菜单做决策** | 吃之前拍窗口价目牌、路边摊招牌或外卖店铺菜单截图;模型读出菜名和价格、估每样的蛋白区间,代码按 分/g 排序,显示"这个菜单里最划算的三样";点一样就记上 | 用户自己拍,不依赖任何学校 | 降低切换成本:零历史也有价值 | 中:一个新的解析分支 + 一个排序页;要把 Non-goal 从"只排序官方数据"放宽到"排序带区间和置信度的数字,文案不出现'应该'" |
| 2 | **下一顿卡片** | 首页常驻:"还差 40 g、今天还剩 18 元,你吃过的里能补上的三样" | 用户自己的记录 | 加法:补上"差额之后去哪"的闭环 | 低:即时回报的逻辑已有,搬到首页 |
| 3 | **拍营养成分表** | 便利店、超市的包装食品:拍营养成分表和价签,直接算 分/g | 包装上的法定标签,高置信度 | 专业性:确定数据不让模型猜 | 低:读表是模型的强项 |
| 4 | **同校榜** | 把同一所学校种子用户校准过的记录汇总成一张静态榜:"本校同学记过的,按 分/g" | 种子用户导出的 JSON,手工汇总 | feed 的轻量版 | 中:先手工,不做后端 |
| 5 | **换一换** | 用自己的记录算假设:"这周 4 顿外卖换成食堂,同样的蛋白省 60 元" | 用户自己的记录 | 用决策级的话表达,而不是单位 | 低 |
| 6 | **14 天蛋白预算体检** | 明说两周一期,期末出一份"蛋白从哪来、钱花在哪"的报告,之后每周记一天 | 用户自己的记录 | 承认记录类产品留存差,把退出设计进去 | 中 |

**建议顺序**:先 2(几天能做完,立刻补上闭环),再 1(这是新的主赌注,把产品从记录工具变成决策工具),然后 3。4 等有种子用户再做,5、6 排后。

**2026-11-04 已采纳**:小红书的帖子标题都在问"吃什么",钱是约束。PRD 把主线从"记下吃了什么"调整为"预算内吃什么",方向 2、1、3 成为 F0(吃之前),Non-goal 放宽为"允许按一个透明指标排序"。还有一个从渠道来的想法:需求聚集在小红书,产品可以产出一张按天的"我的穷鬼增肌日"卡片(吃了什么、多少蛋白、花了多少钱),用户自己发出去。

国外已经有一批"拍菜单看宏量"的 App(MenuCalories、Menu Macros、TasteScan、Menu AI),说明"吃之前拍菜单"这个动作成立;我查到的几款都没有"每一块钱多少蛋白"这个指标。国内有没有同类没查到,需要自己在应用商店搜一次。

## 6. 面试三句话

- 市场定位:饮食记录是红海,我做减法(增肌大学生、蛋白和钱两个数)加一条加法(分/g,每一块钱换多少克蛋白)。
- 和通用 AI 的区别:它是一次问答,我是一本账加一层确定数据;模型认菜,代码算数,输出区间,有评测。
- 和垂类的区别:它们服务减脂、单位是千卡;我服务增肌、单位是钱。下一步不是做更准的识别,而是把记录工具变成"吃之前帮你比"的决策工具。
